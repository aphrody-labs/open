# react/jsx-no-undef

`` reads a variable named `Header`. If nothing declares or imports it, usually because of a typo or a forgotten import, rendering throws a `ReferenceError`.

Names that start with a lowercase letter, such as `<div>` or `<my-element>`, are HTML elements, so the rule skips them. In ``, it only checks `Menu`.

## Configure

Off by default. To turn it on:

```toml bunfig.toml
[lint.rules]
"react/jsx-no-undef" = "error" # or "warn"
```

Every option, set to its default:

```toml bunfig.toml
[lint.rules]
"react/jsx-no-undef" = ["error", {
  allowGlobals = false,
}]
```

## Examples

Reported:

```jsx
  return ;
```

Not reported:

```jsx
}
```

## Options

| Option | Default | What it does |
| --- | --- | --- |
| `allowGlobals` | `false` | Accept components that are global variables. |

By default a global doesn't count in a module, even one you declared:

{/* bad */}
```jsx
/* global Header */

  return ;
}
```

{/* good {"options": [{"allowGlobals": true}]} */}
```jsx
/* global Header */

  return ;
}
```
