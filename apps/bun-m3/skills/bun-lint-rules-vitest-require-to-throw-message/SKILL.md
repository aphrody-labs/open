# vitest/require-to-throw-message

`toThrow()` without an argument passes for any error at all, including a `TypeError` from a typo in the code under test. The test stays green even though the check you meant to test was never reached. Pass part of the message, a regular expression, or the error class.

`.not.toThrow()` is allowed, because there's no error to describe.

## Configure

Off by default. To turn it on:

```toml bunfig.toml
[lint.rules]
"vitest/require-to-throw-message" = "error" # or "warn"
```

## Examples

Reported:

{/* bad {"count": 3} */}
```js

test("rejects a negative amount", async () => {
  expect(() => withdraw(-5)).toThrow();
  expect(() => withdraw(-5)).toThrowError();
  await expect(transfer(-5)).rejects.toThrow();
});
```

Not reported:

{/* good */}
```js

test("rejects a negative amount", async () => {
  expect(() => withdraw(-5)).toThrow("amount must be positive");
  expect(() => withdraw(-5)).toThrow(RangeError);
  await expect(transfer(-5)).rejects.toThrow(/positive/);
});

test("accepts a positive amount", () => {
  expect(() => withdraw(5)).not.toThrow();
});
```
