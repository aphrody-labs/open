# jest/prefer-hooks-in-order

Jest runs hooks in a fixed order: `beforeAll`, `beforeEach`, `afterEach`, `afterAll`. If a file lists them in another order, you read the teardown before the setup it undoes.

Each `describe` block is checked separately. Only hooks that come one right after another are compared. Any other call between two hooks, such as a test, starts a new group.

## Configure

Off by default. To turn it on:

```toml bunfig.toml
[lint.rules]
"jest/prefer-hooks-in-order" = "error" # or "warn"
```

## Examples

Reported:

{/* bad */}
```ts

afterEach(() => {
  db.rollback();
});

beforeEach(() => {
  db.begin();
});
```

Not reported:

{/* good */}
```ts

beforeEach(() => {
  db.begin();
});

afterEach(() => {
  db.rollback();
});
```

The test between these two hooks starts a new group, so this isn't reported. `jest/prefer-hooks-on-top` reports it instead.

{/* good */}
```ts

afterEach(() => {
  db.rollback();
});

test("saves a user", () => {
  db.save(user);
});

beforeEach(() => {
  db.begin();
});
```
