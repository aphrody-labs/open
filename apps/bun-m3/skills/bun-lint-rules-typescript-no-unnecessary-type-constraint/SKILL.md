# @typescript-eslint/no-unnecessary-type-constraint

A type parameter without a constraint already accepts every type. `` and `` say the same thing with more words.

This rule is on by default in TypeScript files.

{/* Generated by src/codegen/lint-rule-docs.ts. Do not edit this section. */}

## Configure

On by default as a warning. To turn it off:

```toml bunfig.toml
[lint.rules]
"@typescript-eslint/no-unnecessary-type-constraint" = "off" # or "error"
```

{/* End of the generated section. */}

## Examples

Reported:

{/* bad {"count": 3} */}
```ts
function first(items: Item[]) {
  return items[0];
}

class Box {
  constructor(public value: Value) {}
}

type Pair = [Left, Right];
```

Not reported:

{/* good */}
```ts
function first(items: Item[]) {
  return items[0];
}

class Box {
  constructor(public value: Value) {}
}

function longest(a: Item, b: Item) {
  return a.length >= b.length ? a : b;
}
```

In a `.tsx` file, `(item: Item) => item` reads as a JSX tag. Write a trailing comma instead of `extends unknown`:

{/* good */}
```tsx
const identity = (item: Item) => item;
```
