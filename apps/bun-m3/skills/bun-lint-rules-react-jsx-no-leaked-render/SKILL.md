# react/jsx-no-leaked-render

`{count && }` evaluates to `count` when `count` is falsy. React renders nothing for `false`, `null` and `undefined`, but it does render `0` and `NaN`, so an empty list shows a stray `0` on the page. In React Native, a number or a string outside `` crashes the app.

The rule reports `&&` in JSX braces, in children and in props, unless its left side looks like a boolean: `!x` or `!!x`, a comparison, any call such as `Boolean(count)`, or a variable declared as `true` or `false`.

`--fix` rewrites the condition with the first allowed strategy.

## Configure

Off by default. To turn it on:

```toml bunfig.toml
[lint.rules]
"react/jsx-no-leaked-render" = "error" # or "warn"
```

Every option, set to its default:

```toml bunfig.toml
[lint.rules]
"react/jsx-no-leaked-render" = ["error", {
  validStrategies = ["ternary", "coerce"],
}]
```

## Examples

Reported:

{/* bad {"count": 2} */}
```jsx
function Cart({ items, note }) {
  return (
    }>
      {items.length && }
    
  );
}
```

Not reported:

{/* good */}
```jsx
function Cart({ items }) {
  return (
    <div>
      {items.length > 0 && }
      {!!items.length && }
      {Boolean(items.length) && }
      {items.length ?  : null}
    </div>
  );
}
```

## Options

| Option | Default | What it does |
| --- | --- | --- |
| `validStrategies` | `["ternary", "coerce"]` | The allowed ways to write a condition. `"ternary"` is `test ?  : null`. `"coerce"` is `&&` with a boolean on the left. |

With only `"ternary"`, every `&&` is reported:

{/* bad {"options": [{"validStrategies": ["ternary"]}]} */}
```jsx
const cart = <div>{!!items.length && }</div>;
```

{/* good {"options": [{"validStrategies": ["ternary"]}]} */}
```jsx
const cart = <div>{items.length ?  : null}</div>;
```

With only `"coerce"`, a ternary is reported too, unless it ends in another element or in a value such as a string:

{/* bad {"options": [{"validStrategies": ["coerce"]}]} */}
```jsx
const cart = <div>{items.length ?  : null}</div>;
```

{/* good {"options": [{"validStrategies": ["coerce"]}]} */}
```jsx
const cart = <div>{items.length > 0 && }</div>;

const list = <div>{items.length ?  : }</div>;

const count = <div>{items.length ? items.length : "none"}</div>;
```

## When not to use it

The rule doesn't use types. So it also reports `{user && }`, even when `user` is an object or `undefined` and nothing can leak.
