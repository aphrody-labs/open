# @next/next/inline-script-id

Next.js uses the `id` of an inline `` to keep track of it, so the code runs once instead of again after each navigation. A script with a `src` is tracked by its URL. An inline script doesn't have one, so it needs an `id`.

A script is inline if it has children or a `dangerouslySetInnerHTML` prop. The rule follows the name you give to the default import of `next/script`.

## Configure

Off by default. To turn it on:

```toml bunfig.toml
[lint.rules]
"@next/next/inline-script-id" = "error" # or "warn"
```

## Examples

Reported:

{/* bad */}
```jsx

  return {`window.startedAt = Date.now();`};
}
```

{/* bad */}
```jsx

  return ;
}
```

Not reported:

{/* good */}
```jsx

  return (
    <>
      {`window.startedAt = Date.now();`}
      
    </>
  );
}
```

If you spread a variable into the props, the `id` might be in there, so the element isn't reported:

{/* good */}
```jsx

  return {`window.startedAt = Date.now();`};
}
```
