# n/no-top-level-await

Node.js can load an ES module with `require()`, but not one that uses `await` at its top level, or one that imports a module like that. In both cases `require()` throws `ERR_REQUIRE_ASYNC_MODULE`. For a published package, that locks out everyone who still uses CommonJS.

`await`, `for await` and `await using` are reported when they're outside of every function.

## Configure

Off by default. To turn it on:

```toml bunfig.toml
[lint.rules]
"n/no-top-level-await" = "error" # or "warn"
```

Every option, set to its default:

```toml bunfig.toml
[lint.rules]
"n/no-top-level-await" = ["error", {
  ignoreBin = false,
}]
```

## Examples

Reported:

{/* bad {"count": 2} */}
```js

for await (const row of db.rows()) {
  console.log(row);
}
```

Not reported:

{/* good */}
```js

let db;

  db ??= await connect();
  return db;
}
```

## Options

| Option | Default | What it does |
| --- | --- | --- |
| `ignoreBin` | `false` | Skip files that start with `#!`. They're run, not imported. |

{/* good {"options": [{"ignoreBin": true}]} */}
```js
#!/usr/bin/env node

await run(process.argv.slice(2));
```

{/* bad */}
```js
#!/usr/bin/env node

await run(process.argv.slice(2));
```

## When not to use it

In an application, or in any module that nobody loads with `require()`, top-level `await` is harmless.
