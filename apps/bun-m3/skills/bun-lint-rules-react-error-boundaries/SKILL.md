# react-hooks/error-boundaries

`` doesn't call `Chart`. It only describes what to render, and React calls the component later, after your function has returned. So if `Chart` throws while rendering, the `try` around the JSX is long over and its `catch` never runs.

To handle a rendering error, wrap the component in an error boundary.

## Configure

Off by default. To turn it on:

```toml bunfig.toml
[lint.rules]
"react-hooks/error-boundaries" = "error" # or "warn"
```

## Examples

Reported:

{/* bad */}
```jsx
function Dashboard({ data }) {
  try {
    return ;
  } catch {
    return <p>Could not draw the chart.</p>;
  }
}
```

Not reported:

{/* good */}
```jsx
function Dashboard({ data }) {
  return (
    Could not draw the chart.</p>}>
      
    
  );
}
```

A `try` around code that runs right away is fine, and so is JSX in the `catch` block:

{/* good */}
```jsx
function Dashboard({ json }) {
  let data;
  try {
    data = JSON.parse(json);
  } catch {
    return <p>Could not read the data.</p>;
  }
  return ;
}
```
